==============================================================
 FRAMEMOD - HUD de frame data para Tekken 6 (PSP / PPSSPP)
 Guia de uso rapida
==============================================================

Que es
------
Una ventana transparente que se coloca encima de PPSSPP y muestra, en vivo,
el startup y la ventaja (on block / on hit) de cada golpe: lo mide leyendo la
memoria del juego, no de una tabla. Funciona con cualquier personaje.

Dos filas: P1 (verde) y P2 (naranja). Cada fila muestra:

    movimiento   startup   ventaja   etiqueta

    P1  1          i10       +8       HIT

Etiquetas:
    TABLA    dato teorico de la tabla local (gris, aun sin medir)
    HIT      el golpe conecto
    BLOCK    el rival lo bloqueo
    PUNISH   castigo: conecto dentro de la ventana de recuperacion
    KND      derribo (no hay ventaja numerica: se muestra "-")

Colores de la ventaja:
    verde    ventaja (+)
    blanco   neutro (0)
    naranja  -1 a -9
    rojo     -10 o peor
    azul     golpe limpio en ventaja

El "~" (ej. ~-12) es el valor medido la ultima vez para ese golpe, mientras se
esta midiendo el nuevo. El numero exacto lo sustituye medio segundo despues.

--------------------------------------------------------------
 1. Arranque rapido
--------------------------------------------------------------
1) Abre PPSSPP y carga Tekken 6 en modo PRACTICA (con el estado guardado que
   uses normalmente).

2) Abre una consola en la carpeta del proyecto y lanza:

       python tools/hud.py

   Si usas el ejecutable empaquetado:

       dist\FRAMEMOD\FRAMEMOD.exe

3) Vuelve a PPSSPP. El HUD aparece solo encima del juego, bajo las barras de
   vida. Es transparente y "click-through": no roba clics ni teclas.

Se cierra solo al cerrar PPSSPP. Solo puede haber una copia: si lanzas otra,
sale con "overlay already running".

--------------------------------------------------------------
 2. Opciones utiles
--------------------------------------------------------------
    python tools/hud.py --debug
        Ademas imprime cada evento en la consola (util para comprobar).

    python tools/hud.py --p1-char bryan --p2-char bruce
        Usa la tabla local y los nombres reales de los golpes.
        Solo hace falta la primera vez: el personaje se recuerda en
        config/hud.json y despues basta con "python tools/hud.py".
        "python tools/hud.py --p1-char none" lo borra.
        Sin personaje el HUD mide igual, pero muestra "#7" en vez del nombre
        y no proyecta el dato teorico de la tabla.

    python tools/hud.py --no-table
        Solo memoria: no proyecta el dato teorico de la tabla.

    python tools/hud.py --no-predict
        No muestra el "~" adelantado.

    python tools/hud.py --x 60 --y 90
        Posicion fija en pantalla (esquinas en pixeles).

    python tools/hud.py --no-click-through
        Permite pinchar la ventana (para depurar; pierdes los clics del juego).

    python tools/hud.py --settings
        Abre el panel de ajustes al arrancar (igual que pulsar F8).

    python tools/hud.py --p1-char bryan --learn
        Aprende IDs de movimientos nuevos: cuando aparece un id desconocido,
        pregunta la notacion por consola (Enter = omitir) y guarda el mapeo.

--------------------------------------------------------------
 3. Panel de ajustes (F8)
--------------------------------------------------------------
Pulsa F8 en cualquier momento (la tecla se puede cambiar en el propio panel,
F7-F12). Permite:

    - mover el HUD (X / Y, vacio = colocado automatico sobre PPSSPP)
    - opacidad (30-100 %)
    - tamano de fuente
    - siempre encima (always on top)
    - tecla de acceso al panel

"Guardar" aplica y escribe config/hud.json. "Aplicar" prueba sin guardar.

--------------------------------------------------------------
 4. Modo demo (sin PPSSPP)
--------------------------------------------------------------
Reproduce una grabacion guardada en .cache/in/ sobre el overlay real. Sirve
para comprobar que la ventana, los colores y la tabla funcionan:

    python tools/hud.py --replay val_1_0
    python tools/hud.py --replay s43a --speed 2     (doble de velocidad)
    python tools/hud.py --replay val_1_0 --speed 0  (sin esperas)

Se cierra solo unos segundos despues de terminar la grabacion.

--------------------------------------------------------------
 5. Probar sin mando (inyectar botones)
--------------------------------------------------------------
Si no puedes usar el mando, se pueden inyectar pulsaciones por el debugger de
PPSSPP (requiere "Remote Debugger" activado, ya lo esta en este perfil):

    python tools/pad.py --daemon        arranca el bus (127.0.0.1:8098)
    python tools/pad.py square          pulsa 1 (jab)
    python tools/pad.py cross           pulsa 3
    python tools/pad.py circle          pulsa 4
    python tools/pad.py --combo square+triangle     1+2
    python tools/demo_live.py moves     secuencia 1, 3, 4, 1+2, 3+4
    python tools/demo_live.py punish    arranca el drill, bloquea y castiga

Mapeo PSP: square=1, triangle=2, cross=3, circle=4.

--------------------------------------------------------------
 6. Golpes bajos (agachado)
--------------------------------------------------------------
Los golpes bajos se bloquean con OTRO estado interno del juego (12329), no con
el bloqueo de pie (4178). El HUD conoce los dos y elige cual esperar segun el
campo "type" de la tabla del movimiento ("l" = low). Ademas exige que el rival
quede trabado de verdad (flag free2 = 0): un amago de guardia (el dummy levanta
la guardia y el golpe pasa de largo) NO se publica como bloqueo.

Como comprobarlo:
    - Pon el dummy en GUARDIA TOTAL y haz un bajo: debe salir BLOCK con su
      ventaja (ej. i12 -15).
    - Pon el dummy en DE PIE y repite: debe salir HIT (ej. i12 -4).
    Los dos numeros son medidas reales del juego.

Los IDs de movimiento se repiten entre posturas: el mismo ID puede ser un "2"
de pie y un "FC.4" agachado, o un "3+4" de pie y un "qcb+3" agachado. El mapa
del personaje lo resuelve con la clave "crouch:<id>":

    { "20": "3+4", "crouch:20": "qcb+3", "10": "2", "crouch:10": "FC.4" }

Con esa entrada el HUD mide y etiqueta el golpe agachado como cualquier otro
(ej. qcb+3 i19 -14). Sin ella no proyecta la tabla y muestra el ID crudo
("#10"): es preferible no ensenar nada a ensenar el nombre y la frame data de
otro movimiento. La medicion (startup y ventaja) es correcta igual.

Si un personaje usa otra variante de guardia agachada, anadela sin tocar
codigo:

    python tools/game_states.py --add-crouch-block 12345

(o deja que --learn te la ofrezca cuando la vea).

--------------------------------------------------------------
 7. Problemas y soluciones
--------------------------------------------------------------
No aparece la ventana:
    - PPSSPP tiene que estar abierto ANTES o durante los primeros 20 s.
    - Comprueba que no haya otra copia: "overlay already running".
    - Prueba "python tools/hud.py --debug" para ver errores en consola.

La ventana esta pero no hay numeros:
    - Debe estar en PRACTICA (el HUD no mide en versus/online).
    - Si el golpe no conecta no hay evento: solo veras el "start".
    - Comprueba que PPSSPP es la version con debugger (1.19.x de este perfil).

Sale "#25" en vez del nombre del golpe:
    - Ese ID no esta mapeado para el personaje. La medicion es correcta igual.
    - Mapealo con --learn o edita data/mappings/<personaje>_map.json.
    - Si es un ataque AGACHADO, es normal: los IDs se repiten entre posturas y
      el HUD prefiere el ID crudo antes que el nombre de otro golpe (ver 6).

Un golpe bajo no muestra nada:
    - Comprueba que conecta: si el dummy lo bloquea debe salir BLOCK.
    - Si el dummy lo bloquea y aun asi no sale nada, el estado de guardia de tu
      personaje puede ser otro: lanza con --learn y anadelo, o usa
      python tools/game_states.py --add-crouch-block <estado>.

El startup sale mas alto de lo normal:
    - En strings (1,1,3...) el segundo golpe se mide desde el inicio del
      string, asi que es normal que salga mas alto que el primer golpe; ademas
      puede ser una variante con datos distintos a la del movimiento suelto.
      Para datos limpios, prueba el golpe suelto.
    - Si vienes de un derribo, espera a que el rival se levante del todo.

La ventaja no aparece (muestra "-"):
    - Tras un KND (derribo) no hay ventaja numerica: es lo correcto.
    - Si el castigo corto la recuperacion, la fila del rival muestra "-".

El HUD se cierra solo:
    - PPSSPP se cerro o se colgo: el watchdog cierra el overlay a los 20 s.

El bus dice "bus has no PPSSPP connection":
    - PPSSPP ya no esta abierto (o el debugger esta desactivado).

--------------------------------------------------------------
 8. Donde esta cada cosa
--------------------------------------------------------------
    tools/hud.py            el HUD (motor + ventana)
    tools/live.py           el mismo motor en consola, sin ventana
    tools/pad.py            inyectar botones por el bus
    tools/demo_live.py      demos de golpes y de PUNISH
    tools/replay.py         repetir una grabacion por consola
    data/compiled/*.json    tablas por personaje (ID -> movimiento)
    data/mappings/*.json    ID del juego -> notacion
    data/states.json        estados que cuentan como bloqueo (pie y bajos)
    config/hud.json         ajustes del panel (se crea al guardar)
    .cache/live_hud.out     log de eventos si lanzas con --debug
